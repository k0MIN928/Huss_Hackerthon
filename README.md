# 💳 모아Sub — 구독 소비 인식 지원 서비스

> HUSS 퓨처아고라 해커톤 MVP
> "구독을 줄이라고 강요하지 않습니다. 스스로 인식하고, 스스로 결정하도록 돕습니다."

---

## 서비스 소개

**모아Sub**는 자동결제 시대에 흩어진 구독 지출을 한눈에 확인하고,
사용자가 각 구독을 **유지·점검·해지 검토 여부를 스스로 선택**할 수 있도록 돕는 구독 소비 인식 지원 서비스입니다.

### 핵심 가치: 인식 → 판단 → 선택

- **인식**: 내 구독 지출 현황을 한눈에 파악한다.
- **판단**: 각 구독이 현재 내 이용 패턴에 맞는지 점검한다.
- **선택**: 유지할지, 점검할지, 해지를 검토할지 스스로 결정한다.

### 핵심 원칙

- 해지를 강요하지 않습니다. "해지 추천"이라는 표현을 사용하지 않습니다.
- 점검 결과는 정답이 아닌 **판단을 돕는 참고 정보**입니다.
- 사용자가 스스로 인식하고 결정하도록 정보를 제공합니다.

## 기술 스택

| 영역 | 기술 |
|------|------|
| Frontend | Streamlit |
| Backend | FastAPI |
| 점검 엔진 | rule-based (backend/rule_engine.py) |
| RAG | SUBSCRIPTION_DB 기반 직접 조회 (subservice/rag_service.py) |

### rule-based 방식을 선택한 이유

실제 사용자 행동 데이터(유지·변경·해지 이력)가 없는 MVP 단계에서
학습 기반 모델을 사용하는 것은 과도한 주장이 될 수 있습니다.
대신 설명 가능하고 투명한 rule-based 점검 기준을 사용하여
사용자가 "왜 이 구독이 점검 후보인지" 직접 확인할 수 있도록 했습니다.

## 실행 방법

### 0. 패키지 설치

```bash
pip install -r requirements.txt
```

### 1. 백엔드 실행

```bash
python -m uvicorn backend.main:app --reload --port 8000
```

### 2. 프론트엔드 실행 (별도 터미널)

```bash
python -m streamlit run frontend/app.py
```

브라우저에서 `http://localhost:8501` 로 접속합니다.

## API 구조

### `POST /analyze`

구독 목록을 분석하고 rule-based 점검 결과를 반환합니다.

#### 요청 JSON

```json
{
  "subscriptions": [
    {
      "service_name": "티빙",
      "category": "OTT",
      "monthly_fee": 13900,
      "usage_count": 2,
      "satisfaction": 2,
      "billing_date": "2026-07-05"
    }
  ],
  "goal": {
    "product_name": "에어팟",
    "target_price": 250000
  }
}
```

> `goal` 필드는 선택 사항입니다.

#### 응답 JSON (주요 필드)

```json
{
  "summary": { ... },
  "goal_simulation": { ... },
  "results": [
    {
      "service_name": "티빙",
      "status": "점검 후보",
      "check_score": 5,
      "priority_level": "주의",
      "rule_reasons": ["같은 OTT 카테고리에 여러 구독이 있습니다.", "..."],
      "rag_explanation": "...",
      "alternatives": ["넷플릭스", "웨이브"],
      "cancel_path": "마이페이지 → 이용권/결제관리 → 해지",
      "cautions": ["남은 이용 기간 확인"]
    }
  ]
}
```

### `GET /health`

```json
{ "status": "ok", "service": "모아Sub API" }
```

## rule-based 점검 기준

### 기본 점수 계산

| 조건 | 점수 |
|------|------|
| 사용 빈도 2회 이하 | +2 |
| 사용 빈도 3~5회 | +1 |
| 만족도 1~2 | +2 |
| 만족도 3 | +1 |
| 월 결제금액 15,000원 이상 | +2 |
| 월 결제금액 10,000~14,999원 | +1 |
| 같은 카테고리 구독 2개 이상 | +1 |
| 같은 카테고리 구독 3개 이상 | +1 추가 |
| 결제일까지 3일 이내 | +2 |
| 결제일까지 4~7일 | +1 |

### 분류 기준

| 점검 점수 | 분류 |
|-----------|------|
| 0~2점 | 유지 후보 |
| 3~5점 | 점검 후보 |
| 6점 이상 | 해지 검토 후보 |

### 카테고리별 예외

| 카테고리 | 예외 처리 |
|----------|-----------|
| 클라우드 | 만족도가 높으면 사용 빈도 낮아도 점수 감소 (백업·저장공간 특성) |
| 생산성 | 만족도 보통 이상이면 점수 감소 (학업·업무 도구 특성) |
| OTT | 중복 + 저사용이면 추가 점수 |
| 쇼핑 | 사용 빈도 높으면 사용 빈도 페널티 없음 (멤버십 혜택 활용) |
| 음악 | 만족도 높으면 점수 감소 (습관적·정서적 서비스 특성) |
| 교육 | 저사용 + 저만족 + 중복이면 추가 점수 (미사용 구독 경향) |

## 페르소나 기반 시연

프론트엔드에 6개의 대표 사용자 유형이 미리 준비되어 있습니다.
페르소나를 선택하면 구독 목록과 목표 소비 정보가 자동으로 채워집니다.

| 페르소나 | 상황 |
|----------|------|
| 대학생 A | OTT 중복 구독, 일부 서비스만 주로 이용 |
| 대학생 B | 클라우드·생산성 도구 의존, 사용 빈도는 낮음 |
| 사회초년생 C | 소액 구독 누적으로 월 지출이 커진 상태 |
| 직장인 D | 무료체험 후 자동결제가 방치된 서비스 다수 |
| 대학생 E | 음악·콘텐츠 고만족으로 유지 가치가 높은 구독 중심 |
| 취업준비생 F | 교육 구독 여러 개 신청 후 실제 이용 빈도 낮음 |

## 목표 소비 선택 시뮬레이션

사용자가 목표 상품과 금액을 입력하면, 구독을 점검했을 때
하루 1만 원 저축 기준 대비 목표 달성 속도가 얼마나 달라지는지 보여줍니다.

- **선택 시뮬레이션**으로 제공하며, 실제 해지를 유도하지 않습니다.
- 계산 기준: 해지 검토 후보 월 요금 합산 (없으면 점검 후보 중 최고액 1개)

## RAG 구조

`subservice/rag_service.py`의 `SUBSCRIPTION_DB`에 11개 서비스 정보가 수록되어 있습니다.
`backend/rag/rag_stub.py`의 `get_rag_explanation`에서 우선순위에 따라 조회합니다.

```
1순위: SUBSCRIPTION_DB 직접 조회 (document, alternatives, cancel_path, caution)
2순위: service_info.csv 서비스명 매칭
3순위: 카테고리 기반 CATEGORY_FALLBACK
4순위: 기타 fallback
```

서비스명 별칭 처리는 `subservice/rag_service.py`의 `SERVICE_ALIASES`에서 관리합니다.
(예: "디즈니플러스" → "디즈니+", "쿠팡와우" → "쿠팡 와우")

> RAG 설명 문장은 반드시 **선택 지원형**으로 작성합니다.
> 금지: "이 서비스를 해지하세요."
> 권장: "이용 빈도가 낮다면 유지 여부를 점검해볼 수 있습니다."

## 향후 발전 계획

- **실제 사용자 행동 데이터 수집**: 유지·변경·해지 경로 조회·실제 해지 여부를 label로 활용한 개인화 모델
- **로그인 기반 이력 저장**: 구독 변경 이력 및 절감액 누적 추적
- **동연령대 평균 구독 지출 비교**: 비슷한 연령대와의 구독 패턴 비교
- **카드사 / 앱스토어 연동**: 자동 구독 감지 및 자동 입력
- **RAG 서비스 확장**: SUBSCRIPTION_DB에 서비스 추가 및 설명 고도화
- **제휴 기반 요금제 변경 연결**: 더 저렴한 플랜으로의 전환 지원
