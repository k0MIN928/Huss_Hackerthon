# 💳 모아Sub — 구독 소비 인식 지원 서비스

> **HUSS 퓨처아고라 해커톤 MVP**
>
> "구독을 줄이라고 강요하지 않습니다. 스스로 인식하고, 스스로 결정하도록 돕습니다."

---

## 서비스 소개

**모아Sub**는 자동결제 시대에 흩어진 구독 지출을 한눈에 확인하고,
사용자가 각 구독을 **유지·점검·해지 검토 여부를 스스로 선택**할 수 있도록 돕는 구독 소비 인식 지원 서비스입니다.

### 핵심 가치: 인식 → 판단 → 선택

| 단계 | 내용 |
|------|------|
| **인식** | 내 구독 지출 현황을 한눈에 파악한다 |
| **판단** | 각 구독이 현재 내 이용 패턴에 맞는지 점검한다 |
| **선택** | 유지할지, 점검할지, 해지를 검토할지 스스로 결정한다 |

### 핵심 원칙

- 해지를 강요하지 않습니다. "해지 추천"이라는 표현을 사용하지 않습니다.
- 점검 결과는 정답이 아닌 **판단을 돕는 참고 정보**입니다.
- 사용자가 스스로 인식하고 결정하도록 정보를 제공합니다.

## 기술 스택

| 영역 | 기술 |
|------|------|
| Frontend | Streamlit + Altair (시각화) |
| Backend | FastAPI + Uvicorn |
| 점검 엔진 | Rule-based (`backend/rule_engine.py`) |
| RAG | SUBSCRIPTION_DB 직접 조회 (`subservice/rag_service.py`) |
| 데이터 처리 | Pandas |
| 유효성 검증 | Pydantic |

### Rule-based 방식을 선택한 이유

실제 사용자 행동 데이터(유지·변경·해지 이력)가 없는 MVP 단계에서
학습 기반 모델을 사용하는 것은 과도한 주장이 될 수 있습니다.
대신 **설명 가능하고 투명한 rule-based 점검 기준**을 사용하여
사용자가 "왜 이 구독이 점검 후보인지" 직접 확인할 수 있도록 했습니다.

## 실행 방법

### 0. 패키지 설치

```bash
pip install -r requirements.txt
```

### 1. 백엔드 실행

```bash
python -m uvicorn backend.main:app --reload --port 8000
```

- 주소: `http://localhost:8000`
- Swagger 문서: `http://localhost:8000/docs`

### 2. 프론트엔드 실행 (별도 터미널)

```bash
python -m streamlit run frontend/app.py
```

- 주소: `http://localhost:8501`

## 주요 기능

### 랜딩 페이지

- 서비스 소개 및 핵심 철학 안내
- 목표 상품·금액 입력 (목표 소비 시뮬레이션용)
- 구독 점검 바로 시작하기

### 구독 입력

- **12개 페르소나 프리셋** — 클릭 한 번으로 구독 목록과 목표 자동 입력

| 페르소나 | 특징 |
|----------|------|
| 대학생 A | OTT 중복 구독, 일부 서비스만 주로 이용 |
| 대학생 B | 클라우드·생산성 도구 의존, 실 사용 빈도 낮음 |
| 사회초년생 C | 소액 구독 누적으로 월 지출이 커진 상태 |
| 직장인 D | 무료 체험 후 자동결제가 방치된 서비스 다수 |
| 대학생 E | 음악·콘텐츠 고만족으로 유지 가치가 높은 구독 중심 |
| 취업준비생 F | 교육 구독 여러 개 신청 후 실제 이용 빈도 낮음 |
| 대학원생 G | 연구·논문 도구 중심, 고사용·고만족 구독 |
| 개발자 H | 개발 AI 도구 다수 (ChatGPT, Cursor, Copilot) + 생활 구독 |
| 콘텐츠 제작자 I | 이미지·음성 AI 도구 + 소비 구독 혼합 |
| 사회초년생 J | 자기계발 구독 과다, 실사용률 낮음 |
| 취업준비생 K | AI 도구 누적 구독, 중복 카테고리 다수 |
| 대학원생 L | 연구 AI + 클라우드 인프라 중심 |

- **직접 입력** — 서비스명, 카테고리, 월 요금, 이용 횟수, 만족도, 결제일 수동 입력
- 구독 추가·삭제 자유롭게 가능

### 분석 결과 대시보드

결과는 4개 탭으로 구성됩니다.

#### 대시보드 탭
- 총 월 지출 / 연간 지출 / 구독 수 / 중복 카테고리 요약 지표
- **카테고리별 월 지출** 가로 막대 차트
- **구독별 월 요금 비교** 가로 막대 차트 (상태별 색상 구분)
- 우선 확인 항목 목록 (상세 설명 탭 바로가기 버튼 포함)

#### 우선 점검 대상 탭
- 점검 후보 / 해지 검토 후보 서비스 전체 목록
- 서비스명, 카테고리, 상태, 우선순위, 점검 점수, 월 요금 표시

#### 전체 구독 목록 탭
- 전체 구독 데이터 테이블 (점검 점수 순 정렬)

#### 상세 설명 탭
- 서비스별 확장 카드
- rule-based 점검 이유, RAG 설명, 대안 서비스, 해지 경로, 주의사항 표시
- 해외 AI 서비스는 환율 안내 문구 포함

### 목표 소비 시뮬레이션

- 목표 상품과 금액을 설정하면 구독 점검 시 **절감 가능 금액** 및 **목표 달성 속도**를 시뮬레이션
- 하루 1만 원 저축 기준 대비 달성 속도가 몇 % 빠른지 표시
- 결과 상단에 **원형 그래프**(상태별 구독 현황)와 나란히 배치
- 목표 미설정 시 잠재 절감액과 활용 예시 (여행, 콘서트 등) 표시

## Rule-based 점검 기준

### 기본 점수 계산

| 조건 | 점수 |
|------|------|
| 사용 빈도 2회 이하 | +2 |
| 사용 빈도 3~5회 | +1 |
| 만족도 1~2 | +2 |
| 만족도 3 | +1 |
| 월 결제금액 15,000원 이상 | +2 |
| 월 결제금액 10,000~14,999원 | +1 |
| 같은 카테고리 구독 2개 이상 | +1 |
| 같은 카테고리 구독 3개 이상 | +1 추가 |
| 결제일까지 3일 이내 | +2 |
| 결제일까지 4~7일 | +1 |

### 분류 기준

| 점검 점수 | 분류 | 우선순위 |
|-----------|------|----------|
| 0~2점 | 유지 후보 | 안정 |
| 3~5점 | 점검 후보 | 주의 |
| 6점 이상 | 해지 검토 후보 | 높음 |

### 카테고리별 예외 처리

| 카테고리 | 예외 처리 |
|----------|-----------|
| 클라우드 | 만족도 높으면 점수 감소 (백업·저장공간 특성) |
| 생산성 | 만족도 보통 이상이면 점수 감소 (업무 도구 특성) |
| OTT | 중복 + 저사용이면 추가 점수 |
| 쇼핑 | 이용 횟수 높으면 빈도 페널티 없음 (멤버십 혜택 활용) |
| 음악 | 만족도 높으면 점수 감소 (습관적·정서적 서비스 특성) |
| 교육 | 저사용 + 저만족 + 중복이면 추가 점수 |

## RAG 구조

`subservice/rag_service.py`의 `SUBSCRIPTION_DB`에 **31개 서비스** 정보가 수록되어 있습니다.

**수록 서비스 목록**

| 카테고리 | 서비스 |
|----------|--------|
| OTT | 넷플릭스, 티빙, 웨이브, 디즈니+, 왓챠, 유튜브 프리미엄 |
| 음악 | 스포티파이, 멜론, 유튜브 뮤직, 애플 뮤직, 벅스 |
| 클라우드 | iCloud, Google One, 네이버 클라우드, OneDrive, Dropbox |
| 쇼핑 | 쿠팡 와우, 네이버 플러스 멤버십 |
| 교육 | 클래스101, 패스트캠퍼스, 밀리의서재 |
| 생산성·AI | Notion AI, Cursor Pro, GitHub Copilot, ChatGPT Plus, Claude Pro, Perplexity Pro, Midjourney, ElevenLabs, Canva Pro |

`backend/rag/rag_stub.py`의 `get_rag_explanation`에서 아래 우선순위로 조회합니다.

```
1순위: SUBSCRIPTION_DB 직접 조회 (document, alternatives, cancel_path, caution)
2순위: service_info.csv 서비스명 매칭
3순위: service_info.csv 카테고리 매칭
4순위: 카테고리 기반 CATEGORY_FALLBACK
```

서비스명 별칭은 `SERVICE_ALIASES`에서 관리합니다.
(예: `"디즈니플러스"` → `"디즈니+"`, `"쿠팡와우"` → `"쿠팡 와우"`)

> **RAG 설명 작성 원칙**
>
> - 금지: "이 서비스를 해지하세요."
> - 권장: "이용 빈도가 낮다면 유지 여부를 점검해볼 수 있습니다."

## 목표 소비 시뮬레이션 계산 방식

1. **해지 검토 후보** 서비스의 월 요금 합산 → 없으면 **점검 후보** 중 가장 높은 금액 1개 선택
2. 선택된 월 절감액을 기준으로 하루 추가 절감액 계산 (`월 절감액 / 30`)
3. 하루 1만 원 저축 기준 대비 목표 달성 속도 (`일 추가절감 / 10,000 × 100`)
4. 목표 상품 미설정 시 잠재 절감액과 정성적 레이블(여행, 콘서트 등)로 대체 표시

## 향후 발전 계획

- **실 사용자 행동 데이터 수집**: 유지·변경·해지 이력을 label로 활용한 개인화 모델
- **로그인 기반 이력 저장**: 구독 변경 이력 및 절감액 누적 추적
- **동연령대 구독 지출 비교**: 비슷한 연령대와의 구독 패턴 비교
- **카드사 / 앱스토어 연동**: 자동 구독 감지 및 자동 입력
- **RAG 서비스 확장**: 서비스 추가 및 설명 고도화
- **제휴 기반 요금제 전환 연결**: 더 저렴한 플랜으로의 전환 지원
